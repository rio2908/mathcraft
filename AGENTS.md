# MathCraft: руководство для AI-агентов

Этот файл — первая точка входа для любого агента, который меняет проект.
Перед правками также прочитайте:

- [`docs/ARCHITECTURE.md`](docs/ARCHITECTURE.md) — устройство программы и состояния;
- [`docs/GAME_DESIGN.md`](docs/GAME_DESIGN.md) — правила, баланс и игровые инварианты;
- [`docs/DEVELOPMENT.md`](docs/DEVELOPMENT.md) — запуск, проверки и сборки.

## Кратко о проекте

MathCraft — детская математическая игра на Pygame в стилистике Minecraft.
Она работает из нескольких небольших Python-модулей в трёх окружениях:

- локально на Windows;
- в браузере через Pygbag/WebAssembly;
- как нативный Android APK через Buildozer/python-for-android.

В проекте нет загружаемых графических или звуковых ресурсов: пиксельная графика
рисуется примитивами Pygame, звуки синтезируются во время выполнения.

## Обязательные игровые инварианты

Не меняйте эти правила случайно:

1. В марафоне ровно 50 островков: 5 биомов по 10 островков.
2. Островки нумеруются от 1 до 50. Нулевого островка на экране нет.
3. Герой получает задание, уже находясь на соответствующем островке. Задание
   десятого островка решается до завершения первых четырёх биомов. На островке
   50 сразу начинается бой с Драконом, без обычного примера на поле.
4. Моб остаётся на островке до победы. Ошибка без тотема возвращает игрока к
   первому заданию текущего биома.
5. Дракон сначала повторяет уникальные ошибки текущего марафона. Одинаковые
   выражения не должны дублироваться в очереди повторения.
6. Каждая не защищённая шлемом ошибка основного маршрута добавляет Дракону одно
   здоровье. Защищённая ошибка сохраняется для разбора, но не усиливает босса.
7. Адаптивные задания заменяют до трёх заданий следующего марафона и не
   увеличивают общую длину игры.
8. Библиотекарь появляется не более одного раза за марафон и даёт только одну
   попытку. Награда — Меч или Книга с зарядами, ремонт одного из них либо
   10 изумрудов; дорогие артефакты и зелья он не выдаёт.
9. Зелье Силы — расходуемое. Игрок сам применяет один флакон к одному выбранному
   мобу; постоянного эффекта быть не должно.
10. Волк снимает мобу два здоровья за правильный ответ и убегает после любых
    двух ошибок игрока.
11. Таймер учитывает только активную игру: `GAME`, `MOB_BATTLE`,
    `SAGE_CHALLENGE`, `BOSS_BATTLE`. Меню, магазин и статистика не входят во
    время прохождения.
12. Новый рекорд означает время хотя бы на одну целую секунду меньше результата
    предыдущего завершённого марафона того же игрока.
13. Каждый профиль имеет отдельное сохранение и историю; старые профили Ксении
    и Насти сохраняют свои уровни сложности после миграции.
14. Заряд артефакта списывается только при срабатывании. Повторный вход в ту же
    встречу не списывает заряд второй раз; при нуле зарядов покупка сохраняется.
15. Жезл лягушки вручную превращает моба в лягушку с одним сердцем; Дракон не
    является целью. Состояние превращения сохраняется на время незавершённого боя.
16. Руна тепла вручную останавливает лечение только раненого Ледяного голема на
    8 секунд. Во время паузы его четырёхсекундный отсчёт не обнуляется.

## Технические инварианты

- Внутреннее разрешение — `1000 × 600`, ориентация — landscape.
- Основной цикл обязан оставаться `async` и выполнять `await asyncio.sleep(0)`
  каждый кадр: это необходимо Pygbag.
- Не добавляйте блокирующие ожидания или сетевые запросы в игровой цикл.
- Сохраняйте крупные кнопки и читаемый шрифт для телефона Redmi Note 7.
- Новые состояния добавляйте одновременно в обработку событий и отрисовку.
- Новые поля сохранения должны получать значения по умолчанию в `get_player()`.
  Старые JSON-файлы обязаны продолжать загружаться.
- Идентификаторы уже существующих предметов, мобов и полей сохранения нельзя
  переименовывать без миграции.
- Сохранение сейчас локальное. Удаление Android-приложения удаляет статистику.
- Не добавляйте реальные ассеты, если тот же результат разумно получить
  существующей кодовой пиксельной отрисовкой.

## Как безопасно менять код

1. Для контента и баланса найдите таблицу в `game_content.py` (`WORLDS`,
   `ARTIFACTS`, `POTIONS`, `MOB_ABILITIES` и т. п.).
2. Для маршрутов и заданий проверьте чистые генераторы в `game_tasks.py`.
3. Проверьте все места, где это состояние сохраняется и сбрасывается.
4. Проверьте обработчик клика в `main()`.
5. Проверьте соответствующую ветку отрисовки `game_state`.
6. Обновите игровую инструкцию и документацию, если правило видно игроку.
7. Выполните проверки из следующего раздела.

Особенно внимательно работайте с глобальными переменными. Если обработчик
события присваивает глобальной переменной новое значение, она должна быть
указана в списке `global` функции `main()`.

## Минимальная проверка перед завершением задачи

В PowerShell:

```powershell
$python = "$env:LOCALAPPDATA\Programs\Python\Python312\python.exe"
& $python -m py_compile main.py game_content.py game_tasks.py game_storage.py
& $python -m pyflakes main.py game_content.py game_tasks.py game_storage.py
& $python -m unittest discover -s tests -v
git diff --check
```

Если используется виртуальное окружение проекта:

```powershell
.\.venv\Scripts\python.exe -m py_compile main.py game_content.py game_tasks.py game_storage.py
.\.venv\Scripts\python.exe -m pyflakes main.py game_content.py game_tasks.py game_storage.py
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

Для изменения механики дополнительно проверьте сценарий функционально. Для UI
запускайте Pygame с dummy-видеодрайвером или web-версию и делайте скриншот
изменённого экрана. После тестов удаляйте только созданные временные каталоги,
не затрагивая пользовательские сохранения.

## Что нельзя считать достаточной проверкой

- только успешный `py_compile` для изменения баланса или сохранений;
- только визуальный скриншот без проверки клика и изменения JSON;
- новый профиль без проверки миграции существующего профиля;
- desktop-экран без проверки размещения элементов в пределах `1000 × 600`;
- успешная web-сборка как доказательство корректности Android-подписи.

## Работа с сохранениями

Файлы `mc_math_save.json` и `mc_last_player.txt` являются пользовательскими
данными и исключены из web-сборки. Не коммитьте их. Не удаляйте и не
перезаписывайте реальные сохранения во время теста — запускайте тест в отдельном
временном рабочем каталоге.

Запись JSON пока не атомарная, а облачной синхронизации и экспорта нет. Если
задача касается надёжности данных, см. ограничения в `docs/ARCHITECTURE.md`.

## Git и область изменений

- Перед правками смотрите `git status --short` и сохраняйте несвязанные изменения.
- Не форматируйте весь `main.py` ради небольшой функции: это затрудняет review.
- Не коммитьте автоматически, если пользователь прямо этого не попросил.
- Не добавляйте `build/`, `bin/`, `.buildozer/`, `__pycache__/` и тестовые
  скриншоты.
