# Публикация MathCraft в RuStore

## Что уже подготовлено

- `.github/workflows/android-rustore.yml` вручную собирает подписанный release
  APK и сохраняет его в артефактах запуска GitHub Actions.
- `buildozer.spec` выпускает release в формате APK; идентификатор приложения —
  `org.game.mathcraft`, начальный `version` — `1.0`, `android.numeric_version` —
  `10000`.
- Отладочный workflow остаётся отдельным и не предназначен для публикации.

Workflow **не публикует приложение автоматически**. Для первой загрузки
понадобятся личный аккаунт владельца в RuStore Консоли, постоянный ключ подписи
и материалы карточки приложения.

## Один раз: ключ подписи

Создайте keystore локально, вне репозитория, и сохраните резервную копию файла
и паролей в надёжном месте. Пример для PowerShell (подставьте свой путь):

```powershell
keytool -genkeypair -v -keystore "C:\<ваша-папка>\mathcraft-release.jks" -alias mathcraft -keyalg RSA -keysize 3072 -validity 36500
```

В настройках репозитория GitHub откройте **Settings → Secrets and variables →
Actions** и добавьте четыре Repository Secrets:

| Секрет | Содержимое |
|---|---|
| `ANDROID_RELEASE_KEYSTORE_BASE64` | Содержимое `.jks` в Base64 |
| `ANDROID_RELEASE_KEYSTORE_PASSWORD` | Пароль хранилища |
| `ANDROID_RELEASE_KEY_ALIAS` | `mathcraft` или выбранный alias |
| `ANDROID_RELEASE_KEY_PASSWORD` | Пароль ключа |

Для получения Base64 в PowerShell можно выполнить локально:

```powershell
[Convert]::ToBase64String([IO.File]::ReadAllBytes("C:\<ваша-папка>\mathcraft-release.jks")) | Set-Clipboard
```

Вставьте содержимое буфера только в соответствующий GitHub Secret. Не
публикуйте его в чате, Issue, логе или коммите. При потере ключа обновления
существующей установки могут стать невозможны.

## Первый выпуск

1. Проверьте в RuStore Консоли, что `org.game.mathcraft` свободен. После первого
   выпуска не меняйте идентификатор без плана миграции данных.
2. Запустите вручную workflow **Build Android Release APK for RuStore** из нужной
   ветки. Скачайте артефакт `MathCraft-Android-RuStore-release` и распакуйте APK.
3. Проверьте APK на настоящем телефоне: запуск, звук, регистрацию профиля,
   несколько ответов, выход и повторный вход, сохранение статистики. Пройдите
   хотя бы один полный марафон.
4. Зарегистрируйте аккаунт в RuStore Консоли, создайте приложение и загрузите
   подписанный APK. Заполните возрастную категорию, описание, контакты,
   иконку, горизонтальные скриншоты и сведения, запрошенные консолью. Отправьте
   выпуск на модерацию.
5. После публикации установите игру на семейные телефоны **из RuStore**.
   Следующие версии загружайте туда же; магазин предложит их как обновление.
   Для обновлений без ручных действий включите в RuStore на каждом телефоне
   **Профиль → Настройки обновлений → Включить**, разрешите ему уведомления,
   фоновую работу и установку приложений. Если обновления не приходят,
   проверьте ограничения батареи для RuStore, особенно на Redmi.

RuStore принимает APK и AAB. Для MathCraft выбран APK: он не требует отдельной
процедуры передачи ключа подписи AAB в магазин. Приложение, выпущенное в
основной каталог, будет доступно не только семье. Закрытое альфа-тестирование
RuStore не стоит использовать как постоянный семейный канал: при его завершении
магазин требует удалить тестовую установку и переустановить основную.

## Каждый следующий выпуск

1. Увеличьте `android.numeric_version` в `buildozer.spec` (например, с `10000`
   до `10001`). При заметном выпуске измените и видимый `version`.
2. Не меняйте `package.domain`, `package.name` и release keystore.
3. Соберите APK тем же workflow; проверьте подпись и сценарий обновления поверх
   предыдущего **release APK** на тестовом телефоне. Убедитесь, что профили и
   статистика остались на месте.
4. Загрузите APK как новую версию в RuStore и дождитесь модерации.

Обычное обновление поверх приложения с тем же package id и подписью сохраняет
его локальные данные. Удаление приложения или очистка его данных — нет.

## Переход с нынешнего debug APK

Существующие домашние установки debug APK могут иметь другую подпись, особенно
если они получены из разных запусков GitHub Actions. Подписанный release APK
нельзя установить поверх них при несовпадении сертификатов. Не удаляйте debug
версию, пока не сохраните нужную статистику: сейчас в игре нет экспорта/импорта,
а удаление Android-приложения удаляет локальные профили. Первый переход на
RuStore — отдельная миграция; последующие обновления release → release уже
смогут идти без удаления при неизменной подписи.
