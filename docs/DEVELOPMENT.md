# Разработка, тестирование и сборка MathCraft

## 1. Поддерживаемые окружения

| Окружение | Python/runtime | Конфигурация |
|---|---|---|
| Windows, локально | Python 3.12 | `requirements-web.txt` |
| Web | Pygbag 0.9.3, WASM | `pygbag.ini`, workflow `build.yml` |
| Android APK | Python 3.10.11 внутри APK | `buildozer.spec`, workflow `android.yml` |

Внутреннее окно игры всегда имеет размер `1000 × 600`. На Android используется
полноэкранный landscape-режим; web workflow добавляет CSS для сохранения
соотношения сторон 5:3.

## 2. Первичная настройка Windows

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install --upgrade pip
.\.venv\Scripts\python.exe -m pip install -r requirements-web.txt
```

Для Pygbag в русской локали Windows задавайте UTF-8:

```powershell
$env:PYTHONUTF8 = "1"
```

## 3. Быстрый локальный запуск

Нативное окно Pygame:

```powershell
.\.venv\Scripts\python.exe main.py
```

Web-сервер:

```powershell
$env:PYTHONUTF8 = "1"
.\.venv\Scripts\python.exe -m pygbag --ume_block 0 .
```

Откройте адрес из вывода Pygbag, обычно `http://localhost:8000`.

## 4. Обязательные статические проверки

```powershell
.\.venv\Scripts\python.exe -m py_compile main.py game_content.py game_tasks.py game_storage.py
.\.venv\Scripts\python.exe -m pyflakes main.py game_content.py game_tasks.py game_storage.py
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
git diff --check
```

Версия Pyflakes в CI зафиксирована в `requirements-web.txt`. Проверка должна
проходить именно на `pyflakes==3.4.0`, если системная версия отличается.

Тесты используют стандартный `unittest` и не требуют отдельной зависимости.
Они проверяют инварианты контента, генерацию маршрутов и заданий, адаптивные
повторы, локальное хранение и headless-запуск приложения. Smoke-тест
автоматически пропускается в окружении без установленного Pygame.

## 5. Headless-проверка Pygame

Для автоматической проверки без видимого окна:

```powershell
$env:SDL_VIDEODRIVER = "dummy"
$env:SDL_AUDIODRIVER = "dummy"
$env:PYGAME_HIDE_SUPPORT_PROMPT = "1"
.\.venv\Scripts\python.exe main.py
```

Приложение имеет безусловный `asyncio.run(main())`, поэтому простой `import
main` запускает игру. Тест, которому нужны функции из модуля, должен:

1. сменить рабочий каталог на временный, чтобы не затронуть реальные сохранения;
2. запустить фоновый поток;
3. дождаться `pygame.display.get_surface()`;
4. отправить `pygame.QUIT` или необходимые события;
5. только после завершения импорта выполнять утверждения.

Для UI-регрессии сохраните поверхность через `pygame.image.save`, визуально
проверьте PNG и удалите его после теста.

## 6. Минимальная ручная матрица проверки

### После изменения маршрута или заданий

- новый профиль начинает с островка 1;
- видны островки 1–10, без островка 0;
- задания 10, 20, 30 и 40 решаются до перехода; на островке 50 сразу
  начинается бой с Драконом;
- пример с пропущенным числом имеет правильный вариант среди трёх;
- ошибка попадает в статистику и очередь Дракона;
- адаптивное задание не увеличивает число островков.

### После изменения мобов или предметов

- моб остаётся видимым до победы;
- способность совпадает с каталогом;
- тотем списывается ровно один раз;
- волк наносит два урона и считает ошибки;
- Зелье Силы списывает один флакон только у выбранного моба;
- артефакт тратит заряд только при срабатывании; ремонт восстанавливает заряды;
- повторный вход в бой не тратит ещё один заряд Меча, Лука или Кристалла;
- Книга скрывает один неверный ответ, затем допускает новое применение только на новом примере;
- Жезл превращает моба в лягушку с одним сердцем, не действует на Дракона и не списывается повторно при перезапуске;
- Руна тепла доступна лишь раненому Ледяному голему, останавливает регенерацию на 8 секунд и сохраняет оставшееся время;
- библиотекарь не выдаёт Лук или Кристалл;
- закрытие и повторный вход не дублируют расходуемый эффект;
- победа очищает временное состояние встречи.

### После изменения сохранений

- новый профиль получает поле по умолчанию;
- профиль из старого минимального JSON успешно мигрирует;
- повторная загрузка не выдаёт награду второй раз;
- профили Ксении и Насти не смешиваются, новые имена также сохраняются отдельно;
- после регистрации выбранные аватар и сложность сохраняются, а следующий
  запуск показывает последнего игрока;
- сброс марафона не удаляет покупки и историю;
- штатный выход сохраняет время.

### После изменения интерфейса

- элементы помещаются в `1000 × 600`;
- текст не выходит за границы кнопок;
- кнопка реагирует по всей видимой области;
- экран читается в альбомной ориентации телефона;
- есть путь назад или выхода из каждого вложенного экрана.

## 7. Web-сборка

Локальная сборка:

```powershell
$env:PYTHONUTF8 = "1"
.\.venv\Scripts\python.exe -m pygbag --build --ume_block 0 .
```

Результат: `build/web`.

При push в `main` workflow `.github/workflows/build.yml`:

1. устанавливает Python 3.12 и web-зависимости;
2. запускает `py_compile` и Pyflakes;
3. собирает Pygbag;
4. исправляет URL BrowserFS для Pygbag 0.9.3;
5. добавляет мобильные viewport/CSS-настройки;
6. публикует результат в GitHub Pages.

Не редактируйте сгенерированный `build/web/index.html`: workflow пересоздаёт и
патчит его при каждой сборке.

## 8. Android APK

Сборка запускается вручную через workflow `.github/workflows/android.yml`.
Результат публикуется как artifact `MathCraft-Android-debug`.

Параметры:

- package id: `org.game.mathcraft`;
- минимальный Android API: 24;
- target/compile API: 34;
- архитектура: `arm64-v8a`;
- bootstrap: SDL2;
- ориентация: landscape;
- backup разрешён (`android.allow_backup = True`).

### Важное ограничение подписи

Workflow сейчас собирает debug APK. На новом GitHub runner debug keystore может
отличаться от ключа предыдущей сборки. Android не установит APK с другой
подписью поверх существующего приложения (`INSTALL_FAILED_UPDATE_INCOMPATIBLE`).
Удаление старого приложения решает установку, но стирает локальную статистику.

Для стабильных обновлений нужен постоянный release keystore:

1. создать ключ один раз и хранить его вне репозитория;
2. сохранить keystore в GitHub Secret в кодировке base64;
3. сохранить alias и пароли в отдельных GitHub Secrets;
4. в workflow восстановить файл и задать переменные
   `P4A_RELEASE_KEYSTORE`, `P4A_RELEASE_KEYSTORE_PASSWD`,
   `P4A_RELEASE_KEYALIAS`, `P4A_RELEASE_KEYALIAS_PASSWD`;
5. собирать `buildozer android release`;
6. никогда не терять и не заменять этот ключ для существующего package id.

До настройки постоянной подписи не обещайте пользователю сохранение данных при
переустановке.

## 9. Сохранения в разных окружениях

| Окружение | Где хранится | Что удаляет данные |
|---|---|---|
| Windows | текущий рабочий каталог | ручное удаление файлов |
| Web | BrowserFS/локальные данные сайта | очистка данных сайта, другой домен/браузер |
| Android | внутреннее хранилище приложения | uninstall или очистка данных приложения |

Файлы сохранения исключены из Pygbag через `pygbag.ini`. Они не должны попадать
в Git.

## 10. Диагностика типичных проблем

### Web показывает белый экран

- откройте консоль браузера;
- проверьте загрузку BrowserFS;
- убедитесь, что workflow выполнил шаг патча Pygbag;
- проверьте, что цикл всё ещё содержит `await asyncio.sleep(0)`.

### Звук отсутствует в браузере

Аудио создаётся только после первого клика/касания. Это ожидаемое ограничение
autoplay. Проверьте `sound_enabled` и вызов `ensure_audio()` из события мыши.

### APK не обновляется поверх установленного

Сравните package id и сертификат подписи. Не советуйте удалять приложение, не
предупредив о потере локальной статистики.

### Новое поле пропадает после перезапуска

Проверьте четыре места:

1. начальный словарь нового профиля;
2. миграцию существующего профиля в `get_player()`;
3. изменение копии профиля, полученной через `load_data()`;
4. вызов `save_data(all_data)` после изменения.

### UI виден, но кнопка не нажимается

Убедитесь, что отрисовка и обработчик используют один и тот же `pygame.Rect`, а
`mouse_pos` обновляется из `event.pos` для мобильного касания.
